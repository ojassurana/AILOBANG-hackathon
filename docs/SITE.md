# Ailobang

A Cloudflare Worker (TypeScript) that serves a landing page, a log-in / sign-up page, and a
post-login page. Sign-in is handled by WorkOS AuthKit; users are stored in Cloudflare D1.

Live at **https://ailobang.com**

## Routes

| Route | Purpose |
| --- | --- |
| `GET /` | Landing page with a "Log in / Sign up" button |
| `GET /signin` | Log-in page (redirects to `/app` if already signed in) |
| `GET /auth/login` | Starts the AuthKit flow: sets a PKCE cookie and redirects to WorkOS |
| `GET /callback` | Exchanges the WorkOS code, upserts the user in D1, sets the session cookie |
| `GET /app` | The post-login page ("Hello World"); redirects to `/signin` when signed out |
| `GET /auth/logout` | Ends the WorkOS session and clears the local cookie |

## How authentication works

The Worker implements the OAuth 2.0 Authorization Code flow against the WorkOS REST API
(`api.workos.com/user_management/*`) using **PKCE**, so no client secret is stored on the
Worker — only the public client id.

1. `/auth/login` generates a `state` and `code_verifier`, stores them in a signed-cookie-free
   short-lived `alb_pkce` cookie, and redirects to AuthKit with `code_challenge`.
2. AuthKit authenticates the user and redirects to `/callback?code=...&state=...`.
3. `/callback` verifies `state`, exchanges the code at `/user_management/authenticate` with the
   `code_verifier`, then writes the user to D1 and issues its own `alb_session` cookie (HMAC-SHA256
   signed, HttpOnly, Secure, SameSite=Lax, 7 days).

Sessions are stateless: the cookie payload is signed with `SESSION_SECRET` in the Worker, so
forging a cookie requires that secret. Verified: a forged cookie is rejected with a redirect
to `/signin`.

## Configuration

`wrangler.jsonc` holds the non-secret config:

- `vars.WORKOS_CLIENT_ID` — the WorkOS environment's client id
- `vars.WORKOS_REDIRECT_URI` — `https://ailobang.com/callback`
- `d1_databases` — binding `DB` → `ailobang-users`
- `routes` — `ailobang.com` as a custom domain
- `assets` — serves `public/` via the `ASSETS` binding with `run_worker_first`, so every request
  passes through the Worker's router before any static file is served

Secrets (set with `npx wrangler secret put <NAME>`):

- `SESSION_SECRET` — 32-byte random string used to sign session cookies

For local development, create `.dev.vars` with `SESSION_SECRET=<value>`.

## WorkOS environment

Currently wired to the **Staging (sandbox)** environment of the "AILobang's Project" WorkOS
project, because the **Production** environment is inactive on the team (`productionState:
Inactive`), and WorkOS rejects config writes against it. Activating production in the WorkOS
dashboard is required before switching.

Configured in that environment:

- Redirect URI: `https://ailobang.com/callback` (default)
- Log-out URI: `https://ailobang.com/` (default)
- CORS origin: `https://ailobang.com`

To switch environments, change `WORKOS_CLIENT_ID` in `wrangler.jsonc`, set the three dashboard
values above for the new environment, and redeploy.

## Commands

```bash
npm install
npm run dev              # local dev server
npm run deploy           # deploy to Cloudflare
npm run types            # regenerate worker-configuration.d.ts (not committed)
npm run migrate:remote   # apply new D1 migrations
npm run tail             # live Worker logs
npx wrangler d1 execute ailobang-users --remote --command "SELECT * FROM users"
```

`worker-configuration.d.ts` is generated by `wrangler types` and is git-ignored, so run
`npm run types` after a fresh clone (or whenever `wrangler.jsonc` changes) to satisfy
typechecking and editor support.

## Database

`migrations/0001_users.sql` creates `users`: one row per WorkOS user, keyed by the WorkOS user
id, with email, name, avatar, verification state, organization id, a sign-in counter, and
timestamps. `/callback` upserts on every login, so repeat sign-ins increment `sign_in_count`
instead of inserting duplicates.

## Notes

- The AuthKit hosted page (WorkOS-hosted) can be branded with Ailobang's logo, colours, and
  copy in the WorkOS dashboard's branding settings.
- A temporary test account exists in the sandbox environment for verification:
  `demo@ailobang.com`. Delete it from the WorkOS dashboard and remove the matching `users` row
  when it is no longer needed.
