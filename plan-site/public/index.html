How it works · six moves

Log in, connect, call, done.

One path, no configuration maze. Everything below happens on Cloudflare at the edge, with state in D1.

01Log in

Email + password

Boring on purpose. One account per person, nothing else to decide.

Password hashed with PBKDF2-SHA256 at the edge, session is an HttpOnly cookie whose token we only store hashed. No passwords in logs, ever.
02See the shelf

A shelf of connectors

The first thing you see after logging in. Gmail today; Calendar, Drive, Slack and the rest as they land.

The catalogue is a table in D1, so adding a tool is a row, not a release. Connector cards show their real state: available, connected, needs re-auth.
03Connect

One click through Composio

You authorise Gmail on Google's own page. We never see a password or a token.

Composio holds the OAuth apps. Each user gets a connected_account_id we store against their row — so the agent can only ever act as the person who authorised it.
04Get a number

You're issued a line

A real Telnyx inbound number, yours, with an add-to-contacts card in the dashboard.

Number → user mapping lives in numbers. When that number rings, we know exactly whose tools to load. First line is already provisioned.
05Call it

GPT-Live 1 picks up

Speech-to-speech. It hears you, cuts in, waits, remembers the thread — like a call, not a transcription pipeline.

Telnyx media stream → voice bridge Worker → a GPT-Live session per call, with your name and your live connectors in the instructions.
06It acts

The agent does the thing

"Read me what's unread." "Reply to him, say I'll be twenty late." It does it and tells you it did.

Tool calls come back to the Worker, get whitelisted, executed through Composio as that user, and logged to call_actions. Destructive steps confirm out loud first.

Why the phone wins
  • It's in your contacts. No app to install, no login on a new device, no tab to find.
  • It works cold. Bad wifi in a lift, hotel landline, your mum's house. The phone network is the most reliable API ever built.
  • It handles interruption. Speech-to-speech means you can cut in mid-sentence — like a person, unlike a queue of prompts.
  • It leaves a receipt. Every call ends with a transcript and a list of actions it actually took. Provable, not vibes.

Edge & compute

Cloudflare Workers

App, API and the voice bridge. Deployed at the edge, no origin server to babysit.

State

D1 SQL

Users, sessions, the connector catalogue, connected accounts, numbers, calls.

Connectors

Composio

Managed OAuth for every toolkit. One connected account per user, revocable in a click.

Telephony

Telnyx

Inbound numbers and media streaming. Real phone lines, real caller IDs.

Voice brain

GPT-Live 1

Speech-to-speech with tool calling. No STT → LLM → TTS relay, so it feels live.

Auth

Email + password

PBKDF2 at the edge, HttpOnly session cookies, rate-limited logins. Nothing exotic.

Straight talk

What's real, and what's still an idea.

Already true

  • The domain, the zone and the hosting for this page.
  • The repo with the full architecture and build order.
  • The phone number, live in the Telnyx account.
  • The Telnyx → GPT-Live inbound bridge pattern — already running for other voice work on the same box.
  • Composio is the chosen connector layer, with the per-user account model worked out.

Still to build

  • The app itself: auth, the shelf, the dashboard.
  • The Composio project + Gmail auth config for AI Lobang customers.
  • Per-user routing on the voice bridge.
  • Composio login on the box (the local CLI session is signed out), then the Gmail connect flow end-to-end.
  • Number strategy: one line per user vs. one shared line with caller-ID mapping.
